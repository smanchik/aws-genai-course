AWS Generative AI · Chapter 1

The AWS Generative AI Service Landscape

You're moving applications from your data center to AWS — and you've been asked to make them smarter along the way. This chapter maps every AWS Generative AI service so you always know which tool fits which job.

Why this matters

Migration + AI enablement, in one motion

Most teams don't adopt GenAI in a vacuum. They adopt it while migrating on-prem workloads — a helpdesk app becomes a self-service assistant, a document archive becomes a searchable knowledge base, a call center gains real-time summarization. AWS packages GenAI as managed services, so you add these capabilities without buying GPUs or hiring an ML research team.

Lift, shift, then light up: the same workloads gain AI capabilities once on AWS.

The mental model

One picture to rule them all: the 4-layer GenAI stack

Every AWS GenAI service lives in one of four layers. Memorize this picture — the rest of the course simply zooms into each layer. The higher the layer, the less you build and the faster you ship.

Center of gravity

Amazon Bedrock — the front door to GenAI on AWS

If you remember one service from this chapter, make it Bedrock. It's a fully managed, serverless service that puts many foundation models behind a single API — no infrastructure, pay per token.

One API. Many models. Zero servers.

Your application sends a request to the Bedrock API; Bedrock routes it to the foundation model you chose. Swap models without rewriting your app — critical when the model landscape changes every month.

The catalog

Every AWS GenAI service, layer by layer

Layer 4 · AI-Powered Applications

Turn-key assistants. Configure, connect your data, done — no ML code.

💼Amazon Q Business

Enterprise AI assistant

A ChatGPT-style assistant grounded in your company's data. 40+ connectors (SharePoint, Salesforce, S3, Confluence…) with permission-aware answers.

On-prem analogy: your intranet search portal — if it could actually answer questions.

👩‍💻Amazon Q Developer

AI coding assistant

Code generation, refactoring, and troubleshooting in your IDE and the AWS console. Includes agents that upgrade Java versions and help plan migrations.

Migration bonus: Q Developer's transformation agent modernizes legacy Java/.NET apps as you move them.

📐Kiro

Agentic IDE

An AI-native development environment that works from specs: it plans, writes, and validates code through structured, spec-driven agentic workflows.

Think of it as: a junior engineer that reads the design doc first.

📞Amazon Connect + Q

AI contact center

Cloud contact center with built-in GenAI: real-time agent assistance, call summarization, and post-contact analytics via Contact Lens.

On-prem analogy: your PBX/call-center stack, minus the hardware, plus an AI copilot for every agent.

📊Amazon Q in Quick Sight

Natural-language BI

Ask questions of your dashboards in plain English ("why did Q3 sales dip?") and get charts, narratives, and data stories generated for you.

On-prem analogy: your BI tool, but the report writes itself.

Layer 3 · Application Tooling (Bedrock capabilities)

The building blocks you'll use most as a developer adding AI to migrated apps.

📚Bedrock Knowledge Bases

Managed RAG

Point it at your documents in S3; it chunks, embeds, and stores them in a vector database so models answer from your data. The full Retrieval-Augmented Generation pipeline, managed.

On-prem analogy: a file share + full-text index, upgraded to understand meaning, not just keywords.

🤖Bedrock Agents & AgentCore

AI that takes action

Agents break a request into steps, call your APIs and Lambda functions, and complete tasks. AgentCore provides the secure, scalable runtime, memory, and identity for production agents.

Think of it as: workflow automation where the workflow figures out its own steps.

🛡️Bedrock Guardrails

Safety & policy layer

Configurable filters for harmful content, denied topics, PII redaction, and hallucination checks — applied consistently across every model you use.

On-prem analogy: the web proxy/DLP appliance of the AI world.

📝Bedrock Prompt Management & Flows

Prompt lifecycle + visual chaining

Version, test, and share prompt templates; visually chain prompts, models, and business logic into multi-step GenAI workflows.

Think of it as: source control + a low-code flow designer for prompts.

🗂️Bedrock Data Automation

Unstructured ➜ structured

Extracts structured insight from documents, images, audio, and video at scale — invoices, claims, contracts, call recordings.

On-prem analogy: your OCR/document-capture suite, generalized to every media type.

🧩Strands Agents (open source)

Code-first agent SDK

AWS's open-source Python SDK for building agents in a few lines of code, with Model Context Protocol (MCP) support for tool integrations.

Pairs with: AgentCore for production hosting.

Layer 2 · Foundation Models as a Service

The "brains" — consumed via API, paid per token.

⚡Amazon Bedrock (core)

Serverless FM access

Single API (InvokeModel / Converse) to many models, with streaming, cross-region inference, fine-tuning, and model evaluation built in.

On-prem analogy: a database connection pool — but for AI models.

✨Amazon Nova

Amazon's own model family

Amazon's frontier models: Nova Micro/Lite/Pro/Premier for text and multimodal reasoning, Nova Canvas (images), Nova Reel (video), and Nova Sonic (speech).

Why care: strong price-performance — often the cost-efficient default.

🧮Amazon Titan

Text & embedding models

Amazon's earlier model family — most notably Titan Text Embeddings, widely used to convert documents into vectors for semantic search and RAG.

Key concept: embeddings = turning text into coordinates so "similar meaning" = "nearby points."

🚀SageMaker JumpStart

Open-model marketplace

Deploy hundreds of open-weight models (Llama, Mistral, Falcon…) onto endpoints you control — when you need models Bedrock doesn't host, or full control.

On-prem analogy: a software repo of pre-built appliances you can self-host — on managed hardware.

Layer 1 · ML Infrastructure

For teams that build, fine-tune, or self-host models. Know these exist; go deep only if needed.

🧪Amazon SageMaker AI

End-to-end ML platform

Build, train, fine-tune, deploy, and monitor models. Hosts custom fine-tuned FMs behind real-time endpoints with autoscaling.

On-prem analogy: your entire ML lab — GPUs, schedulers, model registry — as a managed service.

🔬AWS Trainium & Inferentia

Purpose-built AI chips

AWS-designed silicon: Trainium for training, Inferentia for low-cost inference — significant savings versus GPUs for supported workloads.

Why care: cost optimization questions at scale often end here.

🖥️GPU Instances & UltraClusters

Raw accelerated compute

EC2 P5/P6 (NVIDIA H100/Blackwell) and G6 instances, networked into UltraClusters for large-scale training and inference.

On-prem analogy: the GPU cluster you could never get approved in the capex budget.

Supporting Cast · Pre-GenAI AI services you'll still use

Task-specific AI services that slot into GenAI pipelines (and often answer "which service?" questions).

🔤Amazon Comprehend

NLP & PII detection

Entity extraction, sentiment, and — critically for GenAI — PII detection used in privacy filters before data reaches a model.

🔎Amazon Kendra

Intelligent enterprise search

ML-powered search across enterprise content; frequently used as a high-accuracy retriever inside RAG architectures.

🗣️Transcribe / Polly / Translate

Speech & language

Speech-to-text, text-to-speech, and translation — the input/output adapters for voice-enabled GenAI applications.

📄Amazon Textract

Document extraction

Pulls text, tables, and forms out of scanned documents — a common first step when migrating paper-heavy on-prem processes.

👁️Amazon Rekognition

Image & video analysis

Object detection, face analysis, and content moderation for images and video.

💬Amazon Lex

Conversational bots

Intent-based chat and voice bots (the tech behind Alexa) — now commonly fronting Bedrock-powered conversational experiences.

Data Layer · Where AI memory lives (vector stores)

GenAI apps need databases that search by meaning. These AWS services store embeddings.

🧭OpenSearch Service

Search + vectors

Keyword, semantic, and hybrid search at scale — the most common vector store behind Bedrock Knowledge Bases (including a serverless option).

🐘Aurora PostgreSQL + pgvector

Vectors in your RDBMS

Add vector search to the relational database you already use — ideal when migrating an on-prem PostgreSQL app that needs AI features.

🪣S3 Vectors & others

Low-cost & specialized

S3 Vectors for cost-efficient vector storage at scale; MemoryDB for ultra-low-latency vector search; Neptune Analytics for graph + vectors (GraphRAG).

Cheat sheet

"Which service do I reach for?"

You want to…Reach for
Give employees a chat assistant over company documents — no code Amazon Q Business
Add a "chat with our data" feature inside your own application Bedrock + Knowledge Bases
Automate a multi-step business task (look up order ➜ check policy ➜ issue refund) Bedrock Agents / AgentCore
Keep AI responses safe, on-topic, and free of PII Bedrock Guardrails
Extract data from invoices, contracts, and call recordings Bedrock Data Automation / Textract
Accelerate coding and modernize legacy apps during migration Amazon Q Developer / Kiro
Host an open-weight model with full control SageMaker JumpStart
Fine-tune or train a custom model SageMaker AI (+ Trainium)

🎯 Chapter 1 takeaways

  1. AWS GenAI services form a 4-layer stack: infrastructure → models → tooling → applications. Higher = faster to ship.
  2. Amazon Bedrock is the center of gravity: one serverless API to many foundation models, plus Knowledge Bases, Agents, and Guardrails.
  3. Amazon Q delivers instant wins during migration — Q Business for employees, Q Developer for modernizing code.
  4. Your existing skills transfer: vector stores are databases, Guardrails are policy appliances, Agents are workflow engines.
  5. Migrating first, enabling AI second is the pattern — most AI capabilities bolt onto workloads after they land on AWS.
