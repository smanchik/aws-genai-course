Amazon Q: Instant AI for Your Workforce

Chapters 2–6 taught you to build. This chapter is about what you can simply switch on: Amazon Q Business for employees, Amazon Q Developer for your engineers — the fastest AI wins of any migration program.

7.1 · Where Q fits

Layer 4 revisited: buy the assistant, build the differentiator

Back in Chapter 1's stack, Amazon Q sits at Layer 4 — applications, not building blocks. Everything you've learned (RAG, agents, guardrails) exists inside Q, pre-assembled and managed. The engineering decision is classic buy-vs-build: for internal knowledge assistants and developer tooling, buying usually wins; for customer-facing, differentiated experiences, you build on Bedrock.

7.2 · Q Business

Forty connectors and one crucial filter

Q Business ingests content through pre-built connectors — SharePoint, Confluence, Salesforce, Jira, Google Drive, S3, databases, websites and ~40 more — into a managed index. Crucially, each connector also imports the source system's ACLs, and every answer is filtered by who is asking:

Sync jobs keep the index fresh; the purple gate is what makes Q Business enterprise-grade — users only get answers from documents they could already open.

Migration lens: that S3 connector is your migration dividend. The file shares you lifted into S3 in month one become an answering knowledge base in month two — often the first visible "the cloud made us smarter" moment for the business. Q Business also supports plugins/actions (create a Jira ticket, file a ServiceNow request) — managed agents, in Chapter 5 terms.

7.4 · Q Developer

Q Developer: a pair programmer with AWS in its head

Q Developer lives where your engineers work — IDE (VS Code, JetBrains, Visual Studio), the CLI, and the AWS console. Beyond autocomplete, its agents take on whole tasks: implementing a feature from a description, generating tests and docs, scanning for vulnerabilities, and — the migration headline — upgrading legacy Java applications automatically.

🔄 /transform — legacy upgrades

The transformation agent upgrades Java 8/11 codebases to Java 17+ largely autonomously — dependency bumps, deprecated API rewrites, build verification. Teams report application upgrades in days instead of quarters.

Migration lens: modernize while you migrate, not after.

🧭 Console & CLI assistance

Ask "why can't this Lambda reach RDS?" in the console, or generate CLI commands from plain English. Q has AWS's documentation and your resources' context.

Ops win: the runbook that answers back.

🛡️ Security scanning

Scans code for vulnerabilities and hardcoded secrets as you type, with auto-suggested fixes — the SAST feedback loop reduced from days to seconds.

Bonus: code reviews arrive pre-linted.

7.6 · Buy vs build

Q Business or build on Bedrock?

ScenarioReach forWhy
Employees asking questions over internal content Q Business Connectors + ACLs + UI are already built; you'd spend months re-creating them
Customer-facing chat inside your product Bedrock (build) You need your own UX, branding, model choice, and cost control per request
AI step inside a backend workflow (classify, summarize, route) Bedrock (build) Q is an assistant for humans; workflows want the Converse API + Step Functions
Developers coding, reviewing, upgrading legacy apps Q Developer IDE/console integration and transformation agents are the product
Complex multi-step automation against your APIs Bedrock Agents / Strands Q plugins cover common SaaS actions; custom tools need Chapter 5
Not sure yet — need a visible win this quarter Q Business pilot Weeks to value; what you learn about your data quality transfers to any later build
Rule of thumb: Q for your people, Bedrock for your products. And the combo is common: Q Business for the workforce while the product team builds differentiated features on Bedrock.
7.7 · Field guide

Rollout failures → quick fixes

Indexing everything on day one, including stale file shares
Start with 2–3 curated, high-value sources; garbage in = confidently wrong answers out
Skipping the ACL crawl "to speed up the pilot"
Permissions first — one leaked salary document ends the program
Rolling out to everyone with no champion group
Pilot with one team that has a real pain (e.g., support), measure deflection, expand
No feedback loop on wrong answers
Monitor thumbs-down analytics weekly; fix the source documents — that's usually where the bug is
Comparing Q's per-user price to "free" ChatGPT
Compare to the cost of employees pasting internal data into consumer AI tools

🎯 Chapter 7 takeaways

  1. Amazon Q is Layer 4: RAG + agents + guardrails pre-assembled. Buy it for your people; build on Bedrock for your products.
  2. Q Business = ~40 connectors + managed RAG + permission-aware answers — users only see what their existing ACLs allow.
  3. The S3 connector is your migration dividend: file shares lifted to S3 become an enterprise knowledge base within weeks.
  4. Q Developer pairs with engineers in IDE, CLI, and console — and its /transform agent modernizes legacy Java during migration, not after.
  5. The same Q brain surfaces in Quick Sight, Connect, and Chatbot — instant AI in tools you're already adopting.
  6. Rollout discipline: curated sources first, ACLs always, pilot with champions, and fix wrong answers at the document source.
